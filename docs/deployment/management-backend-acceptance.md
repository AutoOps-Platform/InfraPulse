## Cleanup, operational gate and limitations

Always positively identify project/run/database/loopback binding and SQL marker **before** teardown. Include `--profile fullstack`: ordinary down can omit profiled applications. Use exact project only, never `-v`/prune/broad container removal. Check zero exact-owned containers/networks; preserve ignored evidence if it is the only audit history. Record every background job ID and collect its final output. Compare shared service IDs/healthy state/three volume identities before/after; IDs alone do not prove full data integrity, backup/restoration or unchanged TSDB contents.

Actual shared deployment requires [Gate T12](<management-backend.md>): verified backup and destination, distinct URL roles, protected/readable mounts, owner-only explicit bootstrap→`prisma migrate deploy`→seed, correct fixed source trust, readiness before Gateway. Roll back reviewed schema-compatible **application images** while retaining DB/migrations/volumes/keys. Never destructive schema rollback, privilege/root fallback, automatic password rotation or disabling signatures; incompatible state stays unready for separately approved operator recovery.

Not qualified: real Grafana login/stable SDK subject/React adapter, Telegraf rendering/installer/service/VM behavior, TLS/LAN/production, HA/load/long soak, host ACL portability, CVE/penetration guarantee, historical FAIL/PARTIAL closure or shared rollout. Native Docker Desktop probe results are carrier-specific. A generated fixture is not a production trust decision. Controller owns independent task review and final whole-change review; no staging/commit/push was authorized.
